# TB 问题单评论模板

> 本文件为 connect_TB_workflow 步骤6 的参考文档，按需加载。

## 评论内容结构（书面四段式，结论先行）

> 四段顺序固定：**结论先行 → 证据日志 → 下一步动作 → 修复建议**。
> 面向回传 TB 问题单的书面评论：格式清晰、简练，每段不超过 3-5 行/条。

```markdown
## 🔍 结论

**{一句话核心结论}**

- **问题类型**：{问题类型}
- **严重程度**：{CRITICAL/ERROR/WARNING}
- **根因**：{按可能性排序，1-2 条}

## 📎 证据日志

```
{3-5 条最关键日志，仅保留时间戳 + 核心内容，按时间顺序}
```

## ➡️ 下一步动作

| 优先级 | 动作 | 责任方 |
|--------|------|--------|
| P0 | {动作1} | {责任方} |
| P1 | {动作2} | {责任方} |

## 🛠 修复建议

**短期**：{1-2 条临时方案}
**长期**：{1-2 条根本方案}
**验证**：{1 条核心验证方法}

---
*connect_TB_workflow 自动生成 | {YYYY-MM-DD HH:MM} | 详细报告：{HTML 路径}*
```

## 精简原则

- **评论总长度控制在 2000 字符以内**
- **结论先行**：第一段直接给出一句话结论，读者不用读完即可知道判断
- **关键日志最多 5 条**，仅保留 CRITICAL 级别，独立成「证据日志」段（不要并进结论段）
- **动作清单仅展示 P0/P1**，P2 放到 HTML 报告
- **修复建议每类仅 1-2 条**
- **四段缺一不可**：即使某段无内容也要写「无 / 待补充」，保持结构完整可回传

## 调用参数

> **写回边界（重要）**：本模板仅用于生成**评论草稿**。默认**不自动调用** `CreateTaskCommentV3` 写回；由 TB 看板详情页「AI 分析预览 → 更新评论」按钮在用户确认后写回。仅当用户明确要求直接写回时才可调用。

- 工具：`mcp_teambition-mcp.CreateTaskCommentV3`
- 参数：
  - `taskId`：步骤 2 查询到的系统内部 taskId（不是 shortId）
  - `requestBody.content`：上述精简 Markdown 内容
  - `requestBody.renderMode`：`"markdown"`
  - `requestBody.mentionUserIds`：可选，按需 at 相关责任人

## 异常处理

- 评论创建失败：输出错误信息，但 **不阻塞** 步骤 5 的 HTML 报告输出
- taskId 错误：输出异常并请示用户确认问题单
