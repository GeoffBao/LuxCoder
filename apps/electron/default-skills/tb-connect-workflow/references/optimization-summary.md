# 执行效率优化点汇总

> 本文件为 connect_TB_workflow 的优化点参考文档，按需加载。

## 优化项一览

| 优化项 | 原流程 | 优化后 | 预期收益 |
|--------|--------|--------|---------|
| 附件提取 | 调用 ListTaskActivitiesV3 | 从 QueryTaskV3 的 customfields 直接提取 | 减少 1 次 MCP 调用 |
| 日志下载 | 每次都下载 | 检查本地缓存，命中则跳过 | 避免重复下载 27MB+ 文件 |
| 日志分析 | 每次都调用 skill | 检查已有分析输出，命中则复用 | 避免重复分析（耗时 30s+） |
| 查询参数 | taskId/shortId 混用 | 明确区分，优先用 shortIds | 避免查询失败和重试 |
| 下载重试 | 无重试 | 3 次重试 + 5 秒间隔 | 提高下载成功率 |
| 报告结构 | 4 模块 + 大量元数据 | 3 模块 + 聚焦核心 | 信息密度提升，用户快速获取关键信息 |
| 评论长度 | 无限制（可达 10000 字符） | 2000 字符以内 + 仅 P0/P1 | 避免评论过长，提高可读性 |
| 关键日志 | 15 条 | 5 条 CRITICAL 级别 | 突出最关键证据 |

## 核心优化原则

1. **缓存优先**：下载前检查本地缓存，分析前检查已有输出，避免重复操作
2. **减少 MCP 调用**：能从已有返回结果提取的信息，不额外调用 API
3. **重试兜底**：网络操作必须有重试机制
4. **精简输出**：报告与评论聚焦核心信息，去除冗余元数据
