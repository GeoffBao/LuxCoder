# HTML 报告样式规范

> 本文件为 connect_TB_workflow 步骤5 的参考文档，按需加载。
> **报告采用书面四段式**：结论先行 → 根因 → 证据日志 → 下一步动作 → 修复建议。
> 该结构同时是 TB 看板「AI 分析预览」与评论草稿的提取源，标题须严格按下方命名，便于自动解析。

## 整体风格

- 极简，信息密度高，一眼看到核心结论
- 单栏布局，最大宽度 900px（聚焦核心内容）
- 单文件，内联 CSS，不依赖外部资源
- 编码：UTF-8

## 头部设计

- 紧凑型，仅显示问题单 ID + 标题 + 严重程度标签（1 行）
- 不展示创建人、创建时间等元数据（用户在 TB 上可见）

## 四段式模块（标题命名固定，供 AI 分析预览自动提取）

> 标题用 `##` 级别，依次为：`结论` / `根因` / `证据日志` / `下一步动作` / `修复建议`。
> 每段缺一不可；无内容写「无 / 待补充」。**不要**把问题单标题/描述重复进「结论」段。

### 🔍 结论

- 醒目的蓝色左边框（4px solid），浅蓝背景（#E3F2FD）
- 一句话核心结论：**是什么问题 + 根因一句话判定**（如「根因：SIM 卡在 ATR 阶段无响应（NO_ATR），判定为卡侧故障」）
- **不要**展示问题单标题、创建人、描述等（这些是问题单信息，不是分析结论）
- 结论文字 16px 加粗

### 🔬 根因

- 醒目的红色左边框（4px solid），浅红背景（#FFEBEE）
- 根因定位：一句话根因
- 按可能性排序 1-3 条，每项 1 行（可含「最高嫌疑」标注）

### 📎 证据日志

- 3-5 条关键日志，代码块样式，深色背景（#1A202C）
- 只保留时间戳和核心内容
- 按时间顺序排列

### ➡️ 下一步动作

- 紧凑表格，3 列：`动作 | 责任方 | 验证方法`
- 仅展示 P0/P1（P2 折叠或不展示）
- P0 用红色标签突出
- 每个动作描述不超过 30 字

### 🛠 修复建议

- 简洁列表，不加多余装饰
- 短期：1-3 条临时方案
- 长期：1-3 条根本方案
- 验证：1-2 条核心验证方法

## 配色规范

| 模块 | 主色 | 用途 |
|---|---|---|
| 结论 | `#1976D2`（蓝色） | 核心判定 |
| 根因 | `#D32F2F`（红色） | 问题根因 |
| 下一步动作 | `#F57C00`（橙色） | 提示行动 |
| 修复建议 | `#388E3C`（绿色） | 解决方案 |

## 字体规范

- 正文：14px
- 核心结论：16px 加粗
- 模块标题：16px

## 响应式

- 支持手机和平板访问

## 精简原则

- 报告总长度控制在 2000 字符以内
- 关键日志最多 5 条，仅 CRITICAL 级别
- 动作清单仅 P0/P1
- 修复建议每类仅 1-2 条
