# 侧边栏任务会话层级设计

**日期：** 2026-07-26

## 背景

Task Conductor 运行主任务后，会创建一个 orchestrator 主会话和多个带 `parentSessionId`、`taskSlug`、`taskRunId`、`taskNodeId` 的子任务会话。当前侧边栏的树形展示只把 `parentSessionId + sourceDelegationId` 识别为协作子会话，导致 Task 子任务没有进入同一套树模型：日期模式可能只看到散落的子任务，项目模式则直接过滤所有带 `parentSessionId` 的会话，只显示主任务。

## 方案对比

1. **统一会话树（采用）**：所有父子会话按 `parentSessionId` 建树，再用来源字段区分 Task 与 collaboration。日期、项目、状态、自定义分组和不分组模式都消费同一个树模型。优点是语义一致、不会因切换分组丢会话，并可复用现有展开、缩进和状态聚合。
2. **只修项目过滤**：项目模式不再过滤 Task 子会话，但其他模式仍各自处理。改动小，但不同分组继续表现不一致，后续容易再次回归。
3. **保持平铺，仅加关系 Badge**：不建树，只给子会话加“子任务”标识。标题空间消耗大，主任务进度和状态聚合仍无法表达。

## 统一树模型

新增 renderer 纯函数模块，输出：

- 根会话 `session`；
- 直接子会话 `childSessions`；
- 任务族聚合状态；
- 完成数/总数；
- 任务族活跃时间（根与子会话最新 `updatedAt`）。

只要 `parentSessionId` 指向当前可见集合中的会话，就作为子节点。来源仍保留：`sourceDelegationId` 表示协作子会话，`taskNodeId/taskSlug` 表示 Task 子任务。树模型只统一展示，不改变删除、归档、迁移等现有 collaboration 级联规则，避免扩大操作语义。

孤儿子会话（父会话不存在、被过滤或损坏）自动退化为根行，保证会话永远可见。

## 各分组行为

- **日期**：按根任务族的聚合活跃时间进入日期桶，根行下展开子任务。
- **项目**：按根会话 `projectId` 归项目；项目内按任务族聚合活跃时间排序。子任务跟随主任务，不重复分桶。
- **状态**：按任务族最高优先级状态分桶（blocked > running > completed > idle）。
- **自定义分组**：按根会话 `customGroupId` 分桶，子任务跟随主任务。
- **不分组**：直接显示任务树。
- **置顶**：置顶主任务收纳所有直接子会话；单独置顶的孤立子会话仍可见。

## 视觉与文字容量

侧边栏最小/默认/最大宽度为 240/260/420px。列表项保持 13px 单行标题和至少 28px 行高：

- 子任务仅缩进约 20px，不增加竖向连接线；
- 主任务显示紧凑 `完成数/总数`，不添加“主任务”文字 Badge；
- 子任务使用现有 11px `GitBranch` 图标；
- 长标题继续使用 `MarqueeText`：常态省略，悬浮滚动全文；
- 展开箭头与三点菜单不长期占用标题空间；
- 当前子任务、运行中或需要处理的任务族自动展开，其余默认收起；用户手动收起优先。

## 状态与进度

父行状态取自身及子会话最高优先级。Task 进度总数优先使用 `taskNodeCount`，完成数按每个 `taskNodeId` 的最新会话去重计算，避免重跑后出现 `6/3`；没有 Task 元数据时按直接子会话计数。项目注意力点也使用整个任务族的聚合状态。

## 错误与边界处理

- 父会话缺失：子会话作为根显示；
- 父子归档态不一致：只在当前筛选集合内建树，不跨筛选强行挂载；
- 项目字段不一致：以根会话项目为任务族归属；
- 历史 Task 子会话缺 `taskNodeId`：保留展示，进度按会话完成态兜底；
- 多层关系：当前 UI 仍只展开直接子节点；更深层孤立节点不会消失，但本轮不引入递归多级视觉。

## 测试

新增纯函数测试覆盖 Task、collaboration、孤儿会话、状态聚合、重跑去重进度、聚合活跃时间，以及项目分组不丢子任务。更新侧边栏项目模型测试，并运行 renderer 相关测试、TypeScript typecheck 与 Electron build。
